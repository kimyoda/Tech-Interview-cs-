# 6장 HTTPS·Proxy·Gateway

## 1. HTTPS

HTTPS는 HTTP를 TLS 보호한다. TLS는 통신 내용을 암호화, 전송 중 변조를 탐지, 인증서를 통해 접속한 서버의 신원을 확인하게 한다

```text
클라이언트 - TLS 보호된 HTTP - 서버
```

HTTPS가 제공하는 핵심 속성은 다음과 같음

- 기밀성: 제 3자가 평문 내용을 읽기 어렵게 한다
- 무결성: 전송 중 데이터 변경을 탐지
- 인증: 인증서와 신뢰 체인을 이용해 서버 신원을 검증

TLS 핸드셰이크에서 지원 버전과 암호 스위트를 협상, 서버 인증서를 검증하고, 이후 대칭키 통신에 사용할 키를 합의한다. 실제 데이터는 성능이 좋은 대칭키 암호로 보호한다

HTTPS를 사용해 애플리케이션의 인증·인가, 입력 검증, XSS·SQL Injection 방어가 자동으로 해결되지 않음

## Forward Proxy와 Reverse Proxy

### Forward Proxy

클라이언트를 대신해 외부 서버에 요청한다

```text
클라이언트 -> Forward Proxy -> 인터넷 서버
```

접근 제어, 조직 내부 정책, 익명화, 캐싱 등에 사용할 수 있다. 외부 서버는 프록시의 주소를 보게 된다

### Rverse Proxy

서버 앞에서 클라이언트 요청을 받는다

```text
클라이언트 -> Reverse Proxy -> 앱 서버
```

TLS 종료, 로드 밸런싱, 압축, 캐싱, 정적 파일 제공, 속도 제한 등에 사용할 수 있다. Nginx, Envoy, CDN, 클라우드 로드 밸런서가 이 역할을 할 수 있음

## Gateway

게이트웨이는 서로 다른 시스템이나 프로토콜 사이에 요청을 중계하거나 변환한다. API Gateway는 인증, 라우팅, 속도 제한, 로깅, 응답 결합 같은 공통 기능을 중앙에서 처리할 수 있다

Proxy와 Gateway 용어는 제품과 문맥에 따라 겹친다. 면접에서 이름보다 다음을 분명히 설명하는 편이 좋다

## 관련 상태 코드와 헤더

| 항목                      | 의미                                                                 |
| ------------------------- | -------------------------------------------------------------------- |
| `502 Bad Gateway`         | 상류 서버로 유효하지 않은 응답을 받음                                |
| `503 Service Unavailable` | 서버가 일시적으로 요청을 처리할 수 없다                              |
| `504 Gateway Timeout`     | 상류 서버 응답 제한 시간 안에 받지 못함                              |
| `Forwarded`               | 프록시가 원래 클라이언트, 호스트, 프로토콜 정보를 전달하는 표준 헤더 |
| `X-Forwarded-For`         | 원래 클라이언트 IP 전달에 널리 쓰이는 비표준 헤더                    |

전달 헤더는 사용자가 취조할 수 있어 신뢰할 프록시가 추가하거나 정리한 값만 사용
