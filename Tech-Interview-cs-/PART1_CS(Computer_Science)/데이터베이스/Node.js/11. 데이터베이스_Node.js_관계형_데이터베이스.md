# 관계형 데이터베이스 - 뷰, 옵티마이저, 인덱스

> SQL 문법 밖, 뷰(View), 옵티마이저(Optimizer), 인덱스(Index)

---

## 뷰: 가상 테이블

뷰(View)는 실제 데이터를 저장하지 않고, `SELECT` 쿼리 자체를 저장했다가 조회할 때마다 그 쿼리를 실행하는 가상의 테이블

복잡한 조인을 매번 다시 사용하지 않고, 특정 컬럼을 숨겨서 권한을 제어하는 용도로 쓴다

```sql
CREATE VIEW guild_member_view AS
SELECT
  g.name AS guild_name,
  p.nickname,
  p.level,
  p.vip_grade
FROM guilds g
JOIN players p
  ON g.id = p.guild_id;

-- 복잡한 JOIN을 하나의 테이블로 조회할 수 있음
SELECT *
FROM guild_member_view
WHERE level >= 50;
```

```js
// mysql-view.js

const { getMysqlConnection } = require("./db/mysql");

(async () => {
  const conn = await getMysqlConnection();

  await conn.query(`
    CREATE OR REPLACE VIEW guild_member_view AS
    SELECT
      g.name AS guild_name,
      p.nickname,
      p.level,
      p.vip_grade
    FROM guilds g
    JOIN players p
      ON g.id = p.guild_id
  `);

  const [rows] = await conn.query(
    `SELECT * FROM guild_member_view WHERE level >= 50`,
  );

  console.table(rows);

  await conn.end();
})();
```

MongoDB도 3.4부터 집계 파이프라인을 저장해둔 뷰를 지원. `db.createView()`로 만듦, 내부적으로 `$lookup` 파이프라인이 뷰를 조회할 때 다시 실행

```js
// mongo-view.js

const { getMongoDb, client } = require("./db/mongo");

(async () => {
  const db = await getMongoDb();

  await db
    .createCollection("guildMemberView", {
      viewOn: "players",

      pipeline: [
        {
          $lookup: {
            from: "guilds",
            localField: "guildId",
            foreignField: "_id",
            as: "guild",
          },
        },

        {
          $unwind: "$guild",
        },

        {
          $project: {
            _id: 0,
            nickname: 1,
            level: 1,
            vipGrade: 1,
            guildName: "$guild.name",
          },
        },
      ],
    })
    .catch(() => {}); // 이미 있으면 무시

  const rows = await db
    .collection("guildMemberView")
    .find({
      level: {
        $gte: 50,
      },
    })
    .toArray();

  console.log(rows);

  await client.close();
})();
```

| 항목                     | MySQL                                   | MongoDB                                                      |
| ------------------------ | --------------------------------------- | ------------------------------------------------------------ |
| 생성 문법                | `CREATE VIEW ... AS SELECT ...`         | `db.createView()` / `createCollection({ viewOn, pipeline })` |
| 실제 저장 여부           | 저장 안 됨, 조회 시마다 실행            | 저장 안 됨, 조회 시마다 파이프라인 재실행                    |
| 쓰기 (`INSERT`/`UPDATE`) | 단순한 뷰는 가능, 복잡한 JOIN 뷰는 불가 | 뷰는 항상 읽기 전용                                          |

> 뷰는 읽기 전용으로 취급하는 습관. MySQL은 조건에 따라 뷰를 통한 `UPDATE`/`INSERT`가 가능하나, JOIN이 섞인 뷰는 대부분 막히거나 예상과 다르게 동작, MongoDB 뷰는 애초에 무조건 읽기 전용

## 옵티마이저: 성능 최적화 관리

옵티마이저(Optimizer)는 같은 결과를 내는 여러 실행 방법 중 가장 비용이 적게 드는 방법을 자동으로 골라주는 DB 내부 구성요소.

해당 판단 과정을 직접 눈으로 확인하는 도구는 `EXPLAIN`이다

```sql
EXPLAIN
SELECT *
FROM players
WHERE level >= 50;
```

```js
// mysql-explain.js

const { getMysqlConnection } = require("./db/mysql");

(async () => {
  const conn = await getMysqlConnection();

  const [plan] = await conn.query(
    `EXPLAIN SELECT * FROM players WHERE level >= 50`,
  );

  console.table(plan);

  // type 컬럼이 ALL이면 인덱스를 못 타고 풀 스캔 중

  await conn.end();
})();
```

MongoDB는 `explain()` 메서드로 같은 정보를 확인

```js
// mongo-explain.js

const { getMongoDb, client } = require("./db/mongo");

(async () => {
  const db = await getMongoDb();

  const plan = await db
    .collection("players")
    .find({
      level: {
        $gte: 50,
      },
    })
    .explain("executionStats");

  console.log("실행 단계:", plan.executionStats.executionStages.stage);

  // `COLLSCAN`이면 풀 스캔, `IXSCAN`이면 인덱스

  console.log("검사한 문서 수:", plan.executionStats.totalDocsExamined);

  await client.close();
})();
```

| 항목             | MySQL                              | MongoDB                      |
| ---------------- | ---------------------------------- | ---------------------------- |
| 실행 계획 확인   | `EXPLAIN`                          | `.explain("executionStats")` |
| 풀 스캔 표시     | `type: ALL`                        | `stage: COLLSCAN`            |
| 인덱스 사용 표시 | `type: ref` / `range` / `const` 등 | `stage: IXSCAN`              |

> 쿼리가 느리다는 리포트가 올라오면 `EXPLAIN` 또는 `explain()`을 찍어보는 것.

## 인덱스: 빠른 검색을 위한 데이터 주소

#### 데이터를 조회하는 원리

인덱스가 없으면 DB는 조건에 맞는 행을 찾기 위해 테이블의 처음부터 끝까지 전부 훑어야 한다(Full Scan). 인덱스가 있으면 정렬된 구조(B-Tree)를 따라 훨씬 적은 비교만으로 원하는 행을 찾는다

```text
인덱스 없음

5, 12, 33, 45, 50, 60, 78
-> 순서대로 1개씩 전부 비교
-> O(n)


인덱스 있음 (B-Tree)

level = 50

level < 50, level > 50

등 적은 비교만으로 도달
-> O(log n)
```

```sql
-- 인덱스 생성
CREATE INDEX idx_players_level
ON players(level);

-- 인덱스 확인
SHOW INDEX FROM players;

-- EXPLAIN으로 실제 인덱스 사용 여부
EXPLAIN
SELECT *
FROM players
WHERE level = 50;

-- type: ref, key: idx_players_level이 나오면 인덱스를 탄 것
```

```js
// mysql-index.js

const { getMysqlConnection } = require("./db/mysql");

(async () => {
  const conn = await getMysqlConnection();

  await conn.query(`CREATE INDEX idx_players_level ON players(level)`);

  const [plan] = await conn.query(
    `EXPLAIN SELECT * FROM players WHERE level = 50`,
  );

  console.log("인덱스 사용 여부:", plan[0].key); // 'idx_players_level'이면 인덱스 사용

  await conn.end();
})();
```

```js
// mongo-index.js

const { getMongoDb, client } = require("./db/mongo");

(async () => {
  const db = await getMongoDb();

  await db.collection("players").createIndex({
    level: 1,
  });

  const plan = await db
    .collection("players")
    .find({
      level: 50,
    })
    .explain("executionStats");

  console.log("실행 단계:", plan.executionStats.executionStages.stage); // 'IXSCAN'

  await client.close();
})();
```

> 인덱스는 조회는 빠르게, 쓰기는 느리게. `INSERT` / `UPDATE` / `DELETE`가 일어날 때 인덱스 구조도 같이 갱신. 쓰기가 잦은 테이블에 인덱스를 과하게 걸면 전체 처리량이 떨어진다.

## 마무리

| 개념       | 역할                                               | MySQL                         | MongoDB                         |
| ---------- | -------------------------------------------------- | ----------------------------- | ------------------------------- |
| 뷰         | 복잡한 쿼리를 이름 붙여 재사용, 읽기 전용으로 활용 | `CREATE VIEW`                 | `db.createView()`               |
| 옵티마이저 | 최적의 실행 계획을 자동으로 선택                   | 내장, `EXPLAIN`으로 결과 확인 | 내장, `explain()`으로 결과 확인 |
| 인덱스     | 조회 속도를 O(n)에서 O(log n) 수준으로 단축        | `CREATE INDEX`                | `createIndex()`                 |
