# SQL 함수로 데이터 가공

## SQL 함수 분류

| 분류         | 입력과 출력                           | 예시                               |
| ------------ | ------------------------------------- | ---------------------------------- |
| 단일 행 함수 | 행마다 하나의 결과를 반환             | `CONCAT`, `ROUND`, `DATE_FORMAT`   |
| 집계 함수    | 여러 행을 하나의 값으로 요약          | `COUNT`, `SUM`, `AVG`              |
| 윈도우 함수  | 행을 유지하면서 그룹 계산 결과를 추가 | `RANK`, `ROW_NUMBER`, `SUM() OVER` |

실습을 위해 전적 열을 추가한다.

```sql
ALTER TABLE players
  ADD COLUMN wins INT UNSIGNED NOT NULL DEFAULT 0,
  ADD COLUMN losses INT UNSIGNED NOT NULL DEFAULT 0;
```

## 문자열 함수

```sql
SELECT
  nickname,
  UPPER(nickname) AS upper_name,
  LOWER(nickname) AS lower_name,
  CHAR_LENGTH(nickname) AS char_count,
  CONCAT('[', guild, ']', nickname) AS label
FROM players;
```

| 함수                     | 의미               |
| ------------------------ | ------------------ |
| `CONCAT(a, b, ...)`      | 문자열 연결        |
| `CONCAT_WS(sep, ...)`    | 구분자를 넣어 연결 |
| `CHAR_LENGTH(s)`         | 문자 수            |
| `LENGTH(s)`              | 바이트 수          |
| `UPPER(s)`, `LOWER(s)`   | 대문자·소문자 변환 |
| `TRIM(s)`                | 양쪽 공백 제거     |
| `SUBSTRING(s, pos, len)` | 부분 문자열 추출   |
| `REPLACE(s, from, to)`   | 문자열 치환        |

MySQL의 `CONCAT`은 인수 중 하나라도 `NULL`이면 전체 결과가 `NULL`이 된다.

```sql
SELECT
  CONCAT(
    '[',
    COALESCE(guild, '무소속'),
    ']',
    nickname
  ) AS label
FROM players;
```

## 숫자 함수와 안전한 나눗셈

```sql
SELECT
  nickname,
  wins,
  losses,
  ROUND(
    wins / NULLIF(wins + losses, 0) * 100,
    1
  ) AS win_rate
FROM players;
```

- `NULLIF(a, b)`는 두 값이 같으면 `NULL`, 다르면 `a`를 반환한다.
- 분모가 `0`일 때 `NULLIF(..., 0)`을 사용하면 0으로 나누는 문제를 피할 수 있다.
- `wins + losses`가 `0`이면 `win_rate`는 `NULL`이 된다.

| 함수             | 의미                       |
| ---------------- | -------------------------- |
| `ROUND(n, d)`    | 소수점 `d`자리로 반올림    |
| `TRUNCATE(n, d)` | 소수점 `d`자리 아래를 버림 |
| `CEIL(n)`        | 올림                       |
| `FLOOR(n)`       | 내림                       |
| `ABS(n)`         | 절댓값                     |
| `MOD(a, b)`      | 나머지                     |

정확한 금액이나 비율을 계산할 때는 입력 자료형과 반환 정밀도까지 확인하고 `DECIMAL` 사용을 고려한다.

## 날짜와 시간 함수

```sql
SELECT
  nickname,
  last_login_at,
  DATEDIFF(CURDATE(), last_login_at) AS inactive_days,
  DATE_ADD(last_login_at, INTERVAL 7 DAY) AS reminder_date,
  DATE_FORMAT(last_login_at, '%Y-%m-%d') AS formatted_date
FROM players;
```

| 함수                              | 의미                                        |
| --------------------------------- | ------------------------------------------- |
| `CURDATE()`                       | 현재 날짜                                   |
| `NOW()`                           | 현재 날짜와 시각                            |
| `DATEDIFF(a, b)`                  | `a - b`의 날짜 차이를 일수로 반환           |
| `TIMESTAMPDIFF(unit, a, b)`       | 지정한 단위로 `a`부터 `b`까지의 차이를 반환 |
| `DATE_ADD(date, INTERVAL n unit)` | 날짜 더하기                                 |
| `DATE_SUB(date, INTERVAL n unit)` | 날짜 빼기                                   |
| `DATE_FORMAT(date, format)`       | 날짜를 문자열로 포맷                        |

`DATE_FORMAT`의 결과는 날짜형이 아니라 문자열이다. 날짜 정렬이나 비교에는 가능한 한 원본 날짜 열을 사용하는 것이 안전하다.

`TIMESTAMPDIFF(MONTH, a, b)`는 단순히 달력의 월 숫자 차이를 계산하는 것이 아니라, 두 날짜 사이에 완전히 경과한 월 단위의 차이를 정수로 반환한다.

## 형 변환

```sql
SELECT
  CAST(level AS CHAR) AS level_text,
  CAST('2026-09-02' AS DATE) AS study_date,
  CAST('123.45' AS DECIMAL(10, 2)) AS amount
FROM players
LIMIT 1;
```

암시적 형 변환에 지나치게 의존하면 비교 결과나 인덱스 사용이 예상과 달라질 수 있다.

서로 다른 자료형을 변환해야 한다면 `CAST`를 사용해 의도를 명시한다.

## `NULL` 처리 함수

```sql
SELECT
  nickname,
  COALESCE(guild, '무소속') AS guild_name,
  IFNULL(guild, '무소속') AS guild_name_mysql
FROM players;
```

- `COALESCE(a, b, c)`는 왼쪽부터 확인해 처음 만나는 `NULL`이 아닌 값을 반환한다.
- `IFNULL(a, b)`는 MySQL 전용 함수이며, `a`가 `NULL`이면 `b`를 반환한다.
- 다른 DBMS와의 이식성이 필요하다면 `COALESCE`가 유리하다.

## 조건 함수와 `CASE`

```sql
SELECT
  nickname,
  level,
  CASE
    WHEN level >= 50 THEN 'Master'
    WHEN level >= 40 THEN 'Diamond'
    WHEN level >= 30 THEN 'Gold'
    ELSE 'Rookie'
  END AS tier
FROM players;
```

`CASE`의 조건은 위에서 아래로 평가된다. 따라서 범위가 겹치는 조건에서는 더 엄격한 조건을 먼저 작성한다.

단순 `CASE`도 사용할 수 있다.

```sql
SELECT
  nickname,
  CASE vip_grade
    WHEN 5 THEN 'VVIP'
    WHEN 4 THEN 'VIP'
    ELSE '일반'
  END AS vip_label
FROM players;
```

## 집계 함수와 그룹화

```sql
SELECT
  guild,
  COUNT(*) AS player_count,
  ROUND(AVG(level), 1) AS avg_level,
  MIN(level) AS min_level,
  MAX(level) AS max_level
FROM players
GROUP BY guild;
```

| 함수                         | 의미                   |
| ---------------------------- | ---------------------- |
| `COUNT(*)`                   | 행의 수                |
| `COUNT(column)`              | `NULL`이 아닌 값의 수  |
| `SUM(column)`                | 합계                   |
| `AVG(column)`                | 평균이며 `NULL`은 제외 |
| `MIN(column)`, `MAX(column)` | 최솟값과 최댓값        |

### `WHERE`와 `HAVING`

```sql
SELECT
  guild,
  COUNT(*) AS player_count
FROM players
WHERE level >= 20
GROUP BY guild
HAVING COUNT(*) >= 2
ORDER BY player_count DESC;
```

- `WHERE`는 그룹화 전의 개별 행을 필터링한다.
- `HAVING`은 그룹화 후의 집계 결과를 필터링한다.

처리 흐름을 단순화하면 다음과 같다.

```text
FROM
→ WHERE
→ GROUP BY
→ HAVING
→ SELECT
→ ORDER BY
```

## 윈도우 함수

윈도우 함수는 집계 함수와 달리 원래 행을 줄이지 않고 계산 결과를 덧붙인다.

```sql
SELECT
  nickname,
  guild,
  level,
  RANK() OVER (
    PARTITION BY guild
    ORDER BY level DESC
  ) AS guild_rank
FROM players;
```

| 함수           | 동점 처리                                      |
| -------------- | ---------------------------------------------- |
| `ROW_NUMBER()` | 동점이어도 서로 다른 연속 번호를 부여          |
| `RANK()`       | 동점은 같은 순위이며 다음 순위를 건너뜀        |
| `DENSE_RANK()` | 동점은 같은 순위이며 다음 순위를 연속으로 부여 |

예를 들어 점수가 `100`, `100`, `90`이라면 결과는 다음과 같다.

| 함수           | 순위 결과 |
| -------------- | --------- |
| `ROW_NUMBER()` | `1, 2, 3` |
| `RANK()`       | `1, 1, 3` |
| `DENSE_RANK()` | `1, 1, 2` |

누적 합계도 계산할 수 있다.

```sql
SELECT
  nickname,
  level,
  SUM(level) OVER (
    ORDER BY id
    ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
  ) AS running_level_sum
FROM players;
```

현재 행까지의 `level`을 순서대로 누적하여 계산한다.

## 인덱스와 함수 사용 시 주의점

인덱스가 설정된 열을 함수로 감싸면 일반적인 인덱스 범위 검색이 어려워질 수 있다.

```sql
-- 개선 전
WHERE DATE(created_at) = '2026-09-01'
```

```sql
-- 개선 후
WHERE created_at >= '2026-09-01 00:00:00'
  AND created_at <  '2026-09-02 00:00:00'
```

실제 인덱스 사용 여부는 `EXPLAIN`으로 확인한다.

```sql
EXPLAIN
SELECT id, nickname
FROM players
WHERE last_login_at >= '2026-08-25';
```

## MongoDB 집계 파이프라인

```js
db.players.aggregate([
  {
    $set: {
      guildName: {
        $ifNull: ["$guild", "무소속"],
      },
      tier: {
        $switch: {
          branches: [
            {
              case: { $gte: ["$level", 50] },
              then: "Master",
            },
            {
              case: { $gte: ["$level", 40] },
              then: "Diamond",
            },
            {
              case: { $gte: ["$level", 30] },
              then: "Gold",
            },
          ],
          default: "Rookie",
        },
      },
    },
  },
  {
    $group: {
      _id: "$guildName",
      playerCount: { $sum: 1 },
      avgLevel: { $avg: "$level" },
    },
  },
  {
    $sort: {
      avgLevel: -1,
    },
  },
]);
```

## 핵심 정리

- 단일 행 함수는 행마다 결과를 만든다.
- 집계 함수는 여러 행을 하나의 값으로 요약한다.
- `COALESCE`와 `NULLIF`는 `NULL` 처리와 0으로 나누는 문제를 방지할 때 유용하다.
- `CASE`는 조건에 따라 데이터를 분류하거나 다른 값을 반환한다.
- `WHERE`는 그룹화 전, `HAVING`은 그룹화 후에 데이터를 필터링한다.
- 윈도우 함수는 원래 행을 유지하면서 순위나 누적값을 계산한다.
- 날짜 열을 함수로 감싸기보다 범위 조건을 사용하는 것이 인덱스 활용에 유리할 수 있다.
- 실제 인덱스 사용 여부는 `EXPLAIN`으로 확인한다.
