# 서브쿼리

## 서브쿼리란

- 서브쿼리(Subquery)는 다른 SQL 문 안에 포함된 조회문이다.

```sql
SELECT nickname, level
FROM players
WHERE level > (
  SELECT AVG(level)
  FROM players
);
```

- 바깥 쿼리(Outer Query): 전체 결과를 만드는 쿼리
- 서브쿼리(Inner Query): 바깥 쿼리에 필요한 값이나 행 집합을 제공하는 쿼리

비상관 서브쿼리는 개념적으로 먼저 계산해 사용할 수 있으나, 실제 물리적 실행 순서와 방식은 옵티마이저가 바꿀 수 있다.

## 반환 형태에 따른 분류

| 종류             | 반환 형태 | 주로 사용하는 연산자         |
| ---------------- | --------- | ---------------------------- |
| 스칼라 서브쿼리  | 1행 1열   | `=`, `>`, `<`, 계산식        |
| 단일 행 서브쿼리 | 1행       | 단일값 비교, 행 비교         |
| 다중 행 서브쿼리 | 여러 행   | `IN`, `ANY`, `ALL`, `EXISTS` |
| 다중 열 서브쿼리 | 여러 열   | 행 생성자 비교, `IN`         |

스칼라 위치의 서브쿼리는 다음과 같이 동작한다.

- 1행 반환: 해당 값 사용
- 0행 반환: 보통 `NULL`로 평가
- 2행 이상 반환: 단일값이 아니므로 오류

## 스칼라 서브쿼리

- 전체 평균보다 레벨이 높은 플레이어를 조회한다.

```sql
SELECT nickname, level
FROM players
WHERE level > (
  SELECT AVG(level)
  FROM players
)
ORDER BY level DESC;
```

`SELECT` 절에서도 사용할 수 있다.

```sql
SELECT
  nickname,
  level,
  (SELECT ROUND(AVG(level), 1) FROM players) AS overall_avg_level
FROM players;
```

- 같은 단일값이 모든 행에 반복되므로 의미와 비용을 확인해야 한다.

## 다중 행 서브쿼리와 `IN`

레벨 40 이상 플레이어가 속한 길드의 모든 플레이어를 조회한다.

```sql
SELECT p.nickname, p.guild_id
FROM players AS p
WHERE p.guild_id IN (
  SELECT DISTINCT guild_id
  FROM players
  WHERE level >= 40
    AND guild_id IS NOT NULL
);
```

- `IN`은 목록 중 하나와 같으면 참이다.
- 값 존재 여부가 필요하면 `EXISTS`로도 표현할 수 있다.

## `ANY`, `ALL`

### `ANY`, `SOME`

- 서브쿼리 결과 중 하나 이상과 비교 조건을 만족하면 참이다.

```sql
SELECT nickname, level
FROM players
WHERE level > ANY (
  SELECT level
  FROM players
  WHERE guild_id = 2
);
```

- 서브쿼리가 `NULL`이 아닌 값만 반환하고 비어 있지 않으면 `> ANY`는 최솟값보다 큰 조건과 비슷하다.

### `ALL`

- 서브쿼리 결과의 모든 값과 비교 조건을 만족해야 참이다.

```sql
SELECT nickname, level
FROM players
WHERE level > ALL (
  SELECT level
  FROM players
  WHERE guild_id = 2
);
```

- 같은 전제에서 `> ALL`은 최대값보다 큰 조건과 비슷하다.
- 빈 집합과 `NULL`이 포함된 경우 결과가 달라질 수 있어 무조건 `MIN`, `MAX`와 같다고 단정하면 안 된다.

## `EXISTS`, `NOT EXISTS`

- `EXISTS`는 서브쿼리가 행을 하나라도 반환하는지 확인한다.

```sql
SELECT g.id, g.name
FROM guilds AS g
WHERE EXISTS (
  SELECT 1
  FROM players AS p
  WHERE p.guild_id = g.id
    AND p.level >= 40
);
```

- 플레이어가 없는 길드를 찾는다.

```sql
SELECT g.id, g.name
FROM guilds AS g
WHERE NOT EXISTS (
  SELECT 1
  FROM players AS p
  WHERE p.guild_id = g.id
);
```

`SELECT 1`의 숫자 자체는 중요하지 않다. `EXISTS`는 반환 열이 아니라 행의 존재 여부를 검사한다.

### `NOT IN`, `NULL` 주의

```sql
WHERE id NOT IN (서브쿼리)
```

- 서브쿼리 결과에 `NULL`이 포함되면 3값 논리 때문에 예상과 달리 행이 반환되지 않을 수 있다.
- 부재 여부를 판단할 때 `NOT EXISTS`가 의도를 더 안전하게 표현하는 경우가 많다.

## 상관 서브쿼리

- 상관 서브쿼리는 바깥 쿼리의 현재 행을 참조한다.
- 길드 평균보다 레벨이 높은 플레이어를 조회한다.

```sql
SELECT p.nickname, p.guild_id, p.level
FROM players AS p
WHERE p.guild_id IS NOT NULL
  AND p.level > (
    SELECT AVG(p2.level)
    FROM players AS p2
    WHERE p2.guild_id = p.guild_id
  )
ORDER BY p.guild_id, p.level DESC;
```

- 논리적으로 바깥 행마다 관계된 값을 계산한다.
- 실제 DBMS는 이를 조인이나 다른 실행 전략으로 변환할 수 있다.
- 같은 문제를 집계 결과와 조인으로 표현할 수 있다.

```sql
SELECT p.nickname, p.guild_id, p.level
FROM players AS p
JOIN (
  SELECT guild_id, AVG(level) AS avg_level
  FROM players
  WHERE guild_id IS NOT NULL
  GROUP BY guild_id
) AS ga
  ON ga.guild_id = p.guild_id
WHERE p.level > ga.avg_level;
```

- 성능은 데이터 규모, 인덱스, DBMS 최적화에 따라 달라지므로 `EXPLAIN`으로 비교한다.

## 다중 열 서브쿼리

- 각 길드에서 최고 레벨인 플레이어를 조회한다.

```sql
SELECT p.nickname, p.guild_id, p.level
FROM players AS p
WHERE (p.guild_id, p.level) IN (
  SELECT guild_id, MAX(level)
  FROM players
  WHERE guild_id IS NOT NULL
  GROUP BY guild_id
);
```

- 동점자가 있으면 모두 반환한다.
- 한 명만 필요하면 동점 처리 규칙을 추가해야 한다.

## `FROM` 절 서브쿼리: 인라인 뷰

```sql
SELECT
  ga.guild_id,
  ga.player_count,
  ga.avg_level
FROM (
  SELECT
    guild_id,
    COUNT(*) AS player_count,
    ROUND(AVG(level), 1) AS avg_level
  FROM players
  WHERE guild_id IS NOT NULL
  GROUP BY guild_id
) AS ga
WHERE ga.player_count >= 2
ORDER BY ga.avg_level DESC;
```

- MySQL에서 `FROM` 절 서브쿼리에는 별칭을 지정해야 한다.

## CTE로 가독성 높이기

- 공통 테이블 표현식(Common Table Expression)은 복잡한 중간 결과에 이름을 붙인다.

```sql
WITH guild_stats AS (
  SELECT
    guild_id,
    COUNT(*) AS player_count,
    AVG(level) AS avg_level
  FROM players
  WHERE guild_id IS NOT NULL
  GROUP BY guild_id
)
SELECT
  guild_id,
  player_count,
  ROUND(avg_level, 1) AS avg_level
FROM guild_stats
WHERE player_count >= 2
ORDER BY avg_level DESC;
```

- CTE가 항상 더 빠른 것은 아니며, 주요 장점은 복잡한 쿼리의 구조와 의도를 읽기 쉽게 만드는 것이다.

## 윈도우 함수로 Top-N 처리

- 길드별 상위 3명을 조회한다.

```sql
WITH ranked_players AS (
  SELECT
    id,
    nickname,
    guild_id,
    level,
    ROW_NUMBER() OVER (
      PARTITION BY guild_id
      ORDER BY level DESC, id ASC
    ) AS rn
  FROM players
  WHERE guild_id IS NOT NULL
)
SELECT id, nickname, guild_id, level
FROM ranked_players
WHERE rn <= 3
ORDER BY guild_id, rn;
```

- 정확히 길드당 최대 3행: `ROW_NUMBER()`
- 3위와 동점인 사람들 모두 포함: 요구사항에 따라 `RANK()` 또는 `DENSE_RANK()` 검토

## 서브쿼리, 조인, CTE 선택 기준

| 상황                      | 표현                   |
| ------------------------- | ---------------------- |
| 단일 기준값과 비교        | 스칼라 서브쿼리        |
| 행의 존재 여부            | `EXISTS`, `NOT EXISTS` |
| 여러 테이블 열 함께 출력  | `JOIN`                 |
| 중간 결과를 단계별로 설명 | CTE                    |
| 그룹별 순위, Top-N        | 윈도우 함수 + CTE      |

- 표현 방식보다 정확한 결과가 우선이다.
- 성능은 실행 계획과 실제 데이터로 검증한다.

# MongoDB 대응

전체 평균보다 레벨이 높은 플레이어를 집계 파이프라인으로 조회한다.

```js
db.players.aggregate([
  {
    $setWindowFields: {
      output: {
        overallAvgLevel: {
          $avg: "$level",
          window: {
            documents: ["unbounded", "unbounded"],
          },
        },
      },
    },
  },
  {
    $match: {
      $expr: {
        $gt: ["$level", "$overallAvgLevel"],
      },
    },
  },
  {
    $project: {
      _id: 0,
      nickname: 1,
      level: 1,
      overallAvgLevel: 1,
    },
  },
]);
```

- 다른 컬렉션의 존재 여부는 `$lookup`과 결과 배열 크기로 판단할 수 있다.
- 데이터 모델에 따라 포함(Embedding)이 더 단순한 해결책일 수도 있다.

# 핵심 정리

- 서브쿼리는 반환 행, 열 수에 맞는 비교 연산자와 함께 사용한다.
- 스칼라 서브쿼리가 여러 행을 반환하면 오류가 발생한다.
- 존재 여부에는 `EXISTS`, `NOT EXISTS`가 의도를 잘 드러낸다.
- 상관 서브쿼리는 바깥 행을 참조하며, 조인으로 다시 표현할 수 있다.
- 인라인 뷰와 CTE는 중간 결과를 구조화한다.
- 실제 성능은 문법만으로 단정하지 말고 `EXPLAIN`과 측정으로 확인한다.

const players = await db

## 2. VIP 4등급 이상 플레이어가 존재하는 길드만 조회

```sql
SELECT g.id, g.name
FROM guilds AS g
WHERE EXISTS (
  SELECT 1
  FROM players AS p
  WHERE p.guild_id = g.id
    AND p.vip_grade >= 4
);
```

### MongoDB

```js
db.guilds.aggregate([
  {
    $lookup: {
      from: "players",
      let: {
        guildId: "$_id",
      },
      pipeline: [
        {
          $match: {
            $expr: {
              $and: [
                {
                  $eq: ["$guild_id", "$$guildId"],
                },
                {
                  $gte: ["$vip_grade", 4],
                },
              ],
            },
          },
        },
        {
          $limit: 1,
        },
      ],
      as: "vipPlayers",
    },
  },
  {
    $match: {
      "vipPlayers.0": {
        $exists: true,
      },
    },
  },
  {
    $project: {
      vipPlayers: 0,
    },
  },
]);
```

`$limit: 1`을 넣은 것은 존재 여부만 확인하면 되기 때문이다.

## 3. 플레이어가 없는 길드를 `NOT EXISTS`로 조회

```sql
SELECT g.id, g.name
FROM guilds AS g
WHERE NOT EXISTS (
  SELECT 1
  FROM players AS p
  WHERE p.guild_id = g.id
);
```

```text
guild 1 -> players 중 guild_id = 1 존재? -> 없음 -> 출력
guild 2 -> players 중 guild_id = 2 존재? -> 있음 -> 제외
```

### MongoDB

```js
db.guilds.aggregate([
  {
    $lookup: {
      from: "players",
      localField: "_id",
      foreignField: "guild_id",
      as: "players",
    },
  },
  {
    $match: {
      players: {
        $eq: [],
      },
    },
  },
  {
    $project: {
      players: 0,
    },
  },
]);
```

다음처럼 배열의 첫 번째 요소가 존재하지 않는지 확인할 수도 있다.

```js
{
  $match: {
    "players.0": {
      $exists: false,
    },
  },
}
```

## 4. 각 길드 최고 레벨 플레이어를 다중 열 서브쿼리로 조회

```sql
SELECT
  p.nickname,
  p.guild_id,
  p.level
FROM players AS p
WHERE (p.guild_id, p.level) IN (
  SELECT
    guild_id,
    MAX(level)
  FROM players
  WHERE guild_id IS NOT NULL
  GROUP BY guild_id
);
```

### MongoDB

```js
db.players.aggregate([
  {
    $match: {
      guild_id: {
        $ne: null,
      },
    },
  },
  {
    $setWindowFields: {
      partitionBy: "$guild_id",
      output: {
        maxLevel: {
          $max: "$level",
          window: {
            documents: ["unbounded", "unbounded"],
          },
        },
      },
    },
  },
  {
    $match: {
      $expr: {
        $eq: ["$level", "$maxLevel"],
      },
    },
  },
  {
    $project: {
      _id: 0,
      nickname: 1,
      guild_id: 1,
      level: 1,
    },
  },
]);
```

## 5. `NOT IN`과 `NULL` 조합이 위험한 이유 설명

- 서브쿼리 결과에 `NULL`이 포함되면 3값 논리 때문에 행이 반환되지 않을 수 있다.

→ `NOT IN`의 서브쿼리 결과에 `NULL`이 포함되면 SQL의 3값 논리에 의해 비교 결과가 `UNKNOWN`이 될 수 있다.

`WHERE`에서는 `TRUE`인 행만 통과하므로 예상과 달리 결과가 반환되지 않을 수 있다.

```sql
SELECT id
FROM guilds
WHERE id NOT IN (
  SELECT guild_id
  FROM players
);
```

### 안전한 방법

```sql
SELECT g.id, g.name
FROM guilds AS g
WHERE NOT EXISTS (
  SELECT 1
  FROM players AS p
  WHERE p.guild_id = g.id
);
```

또는 `NULL`을 제거한다.

```sql
SELECT id, name
FROM guilds
WHERE id NOT IN (
  SELECT guild_id
  FROM players
  WHERE guild_id IS NOT NULL
);
```

## 6. 길드별 상위 2명을 윈도우 함수, CTE로 조회

```sql
WITH ranked_players AS (
  SELECT
    id,
    nickname,
    guild_id,
    level,
    ROW_NUMBER() OVER (
      PARTITION BY guild_id
      ORDER BY level DESC, id ASC
    ) AS rn
  FROM players
  WHERE guild_id IS NOT NULL
)
SELECT
  id,
  nickname,
  guild_id,
  level
FROM ranked_players
WHERE rn <= 2
ORDER BY guild_id, rn;
```

- `ROW_NUMBER()`는 길드당 정확히 최대 2명을 반환한다.
- `RANK()`, `DENSE_RANK()`는 순위 기준으로 조회할 경우 2위와 동점인 사람도 모두 포함할 수 있다.

### MongoDB

MongoDB에서는 `$setWindowFields`를 사용한다.

```js
db.players.aggregate([
  {
    $match: {
      guild_id: {
        $ne: null,
      },
    },
  },
  {
    $setWindowFields: {
      partitionBy: "$guild_id",
      sortBy: {
        level: -1,
        _id: 1,
      },
      output: {
        ranking: {
          $documentNumber: {},
        },
      },
    },
  },
  {
    $match: {
      ranking: {
        $lte: 2,
      },
    },
  },
  {
    $project: {
      _id: 1,
      nickname: 1,
      guild_id: 1,
      level: 1,
      ranking: 1,
    },
  },
]);
```

`ROW_NUMBER()`와 비슷한 역할을 하는 것은 `$documentNumber`라고 할 수 있다.
