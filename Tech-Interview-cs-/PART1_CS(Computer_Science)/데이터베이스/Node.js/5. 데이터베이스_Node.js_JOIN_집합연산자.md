# `JOIN`과 집합 연산자

## `JOIN` 목적

- 정규화된 데이터는 여러 테이블에 나뉘어 저장한다.
- `JOIN`은 관련 열을 기준으로 여러 테이블을 하나의 조회 결과로 결합한다.

```sql
SELECT
  p.nickname,
  p.level,
  g.name AS guild_name
FROM players AS p
JOIN guilds AS g
  ON g.id = p.guild_id;
```

`JOIN`만 작성하면 일반적으로 `INNER JOIN`을 뜻한다.

MongoDB에서는 관계형 데이터베이스의 `JOIN`과 비슷한 작업을 주로 `$lookup`을 사용해서 처리한다.

예를 들어 `players.guildId`와 `guilds._id`를 연결한다.

```js
db.players.aggregate([
  {
    $lookup: {
      from: "guilds",
      localField: "guildId",
      foreignField: "_id",
      as: "guild",
    },
  },
]);
```

MongoDB의 `$lookup` 결과는 기본적으로 연결된 문서가 배열 형태로 들어간다.

```js
{
  nickname: "Neo",
  level: 40,
  guildId: ObjectId("..."),
  guild: [
    {
      _id: ObjectId("..."),
      name: "Red Knights"
    }
  ]
}
```

하나의 길드만 연결되는 구조라면 `$unwind`를 사용하여 배열을 하나의 문서처럼 펼칠 수 있다.

```js
db.players.aggregate([
  {
    $lookup: {
      from: "guilds",
      localField: "guildId",
      foreignField: "_id",
      as: "guild",
    },
  },
  {
    $unwind: "$guild",
  },
  {
    $project: {
      _id: 0,
      nickname: 1,
      level: 1,
      guildName: "$guild.name",
    },
  },
]);
```

## `INNER JOIN`

- 양쪽 테이블에서 조인 조건을 만족하는 행만 반환한다.

```sql
SELECT
  p.id,
  p.nickname,
  g.name AS guild_name
FROM players AS p
INNER JOIN guilds AS g
  ON g.id = p.guild_id
ORDER BY p.id;
```

`Equi Join`은 `=` 조건을 사용하는 조인 방식이고, `INNER JOIN`은 일치하지 않는 행을 제외하는 결과 범위를 뜻한다.

두 용어는 기준이 다르므로 완전히 같은 의미는 아니다.

### MongoDB에서 `INNER JOIN`과 비슷하게 처리

MongoDB의 `$lookup` 자체는 일치하는 데이터가 없어도 원본 문서를 유지한다.

따라서 `$unwind`를 사용하면서 일치하지 않는 배열을 제거하면 `INNER JOIN`과 비슷한 결과를 만들 수 있다.

```js
db.players.aggregate([
  {
    $lookup: {
      from: "guilds",
      localField: "guildId",
      foreignField: "_id",
      as: "guild",
    },
  },
  {
    $unwind: "$guild",
  },
  {
    $project: {
      _id: 0,
      id: 1,
      nickname: 1,
      guildName: "$guild.name",
    },
  },
]);
```

길드가 존재하지 않는 플레이어는 `$unwind` 단계에서 결과에서 제외된다.

## `LEFT JOIN`, `RIGHT JOIN`

### `LEFT JOIN`

- 왼쪽 테이블의 모든 행을 유지한다.
- 오른쪽에서 일치하는 행이 없으면 오른쪽 테이블의 열은 `NULL`로 반환된다.

```sql
SELECT
  p.nickname,
  g.name AS guild_name
FROM players AS p
LEFT JOIN guilds AS g
  ON g.id = p.guild_id
ORDER BY p.id;
```

예를 들어 플레이어 데이터가 다음과 같다고 가정한다.

```text
players

id | nickname | guild_id
---|----------|---------
1  | Neo      | 10
2  | Alice    | NULL
```

길드 데이터가 다음과 같다면

```text
guilds

id | name
---|------------
10 | Red Knights
```

결과는 다음과 비슷하다.

```text
nickname | guild_name
---------|------------
Neo      | Red Knights
Alice    | NULL
```

### 길드가 없는 플레이어 찾기

```sql
SELECT
  p.id,
  p.nickname
FROM players AS p
LEFT JOIN guilds AS g
  ON g.id = p.guild_id
WHERE g.id IS NULL;
```

`LEFT JOIN`으로 모든 플레이어를 유지한 다음, 오른쪽 길드가 존재하지 않는 행만 찾는다.

---

### MongoDB의 `LEFT JOIN`

MongoDB의 `$lookup`은 기본적으로 왼쪽 컬렉션의 문서를 유지하므로 `LEFT JOIN`과 비슷하다.

```js
db.players.aggregate([
  {
    $lookup: {
      from: "guilds",
      localField: "guildId",
      foreignField: "_id",
      as: "guild",
    },
  },
  {
    $unwind: {
      path: "$guild",
      preserveNullAndEmptyArrays: true,
    },
  },
  {
    $project: {
      _id: 0,
      nickname: 1,
      guildName: "$guild.name",
    },
  },
]);
```

`preserveNullAndEmptyArrays: true`를 사용하면 연결되는 길드가 없는 플레이어도 결과에 남는다.

길드가 없는 플레이어만 조회하려면 다음처럼 처리할 수 있다.

```js
db.players.aggregate([
  {
    $lookup: {
      from: "guilds",
      localField: "guildId",
      foreignField: "_id",
      as: "guild",
    },
  },
  {
    $match: {
      guild: {
        $eq: [],
      },
    },
  },
  {
    $project: {
      _id: 0,
      nickname: 1,
      guildId: 1,
    },
  },
]);
```

---

### `RIGHT JOIN`

오른쪽 테이블의 모든 행을 유지한다.

```sql
SELECT
  p.nickname,
  g.name AS guild_name
FROM players AS p
RIGHT JOIN guilds AS g
  ON g.id = p.guild_id;
```

대부분의 경우 테이블 순서를 바꾼 `LEFT JOIN`으로 같은 의미를 표현할 수 있다.

```sql
SELECT
  p.nickname,
  g.name AS guild_name
FROM guilds AS g
LEFT JOIN players AS p
  ON p.guild_id = g.id;
```

코드의 일관성을 위해 `LEFT JOIN`을 주로 사용하는 경우가 많다.

### MongoDB에서 `RIGHT JOIN`

MongoDB에는 `RIGHT JOIN`이라는 별도의 연산자가 없다.

기준 컬렉션을 반대로 선택해서 `$lookup`하면 된다.

```js
db.guilds.aggregate([
  {
    $lookup: {
      from: "players",
      localField: "_id",
      foreignField: "guildId",
      as: "players",
    },
  },
]);
```

즉

```text
SQL

players RIGHT JOIN guilds
```

를 MongoDB에서는

```text
guilds를 기준 컬렉션으로 조회
-> players를 $lookup
```

하는 방식으로 표현할 수 있다.

## 외부 조인에서 `ON`, `WHERE`

필터의 위치에 따라 결과가 달라질 수 있다.

### `ON`에서 조건을 적용

```sql
-- 모든 길드를 유지하고 레벨 30 이상 플레이어만 연결

SELECT
  g.name,
  p.nickname,
  p.level
FROM guilds AS g
LEFT JOIN players AS p
  ON p.guild_id = g.id
 AND p.level >= 30;
```

길드 자체는 모두 유지한다.

플레이어가 없거나 레벨 30 이상인 플레이어가 없어도 길드는 결과에 남는다.

### `WHERE`에서 조건을 적용

```sql
-- 조인 후 레벨 30 미만 및 플레이어가 없는 길드 제거

SELECT
  g.name,
  p.nickname,
  p.level
FROM guilds AS g
LEFT JOIN players AS p
  ON p.guild_id = g.id
WHERE p.level >= 30;
```

두 번째 쿼리는 `WHERE`에서 오른쪽 테이블의 `NULL` 행을 제거하기 때문에 결과적으로 `INNER JOIN`과 비슷한 결과가 될 수 있다.

### MongoDB에서 비슷한 차이

`$lookup` 내부에서 조건을 적용하면 SQL의 `ON` 조건과 비슷한 방식으로 사용할 수 있다.

```js
db.guilds.aggregate([
  {
    $lookup: {
      from: "players",
      let: {
        guildId: "$_id",
      },
      pipeline: [
        {
          $match: {
            $expr: {
              $and: [
                {
                  $eq: ["$guildId", "$$guildId"],
                },
                {
                  $gte: ["$level", 30],
                },
              ],
            },
          },
        },
      ],
      as: "players",
    },
  },
]);
```

이 경우 레벨 30 이상 플레이어가 없어도 원본 `guilds` 문서는 유지된다.

반대로 `$lookup` 이후 `$unwind`하고 `$match`를 적용하면 조건에 맞지 않는 문서가 최종 결과에서 제거될 수 있다.

```js
db.guilds.aggregate([
  {
    $lookup: {
      from: "players",
      localField: "_id",
      foreignField: "guildId",
      as: "player",
    },
  },
  {
    $unwind: {
      path: "$player",
      preserveNullAndEmptyArrays: true,
    },
  },
  {
    $match: {
      "player.level": {
        $gte: 30,
      },
    },
  },
]);
```

## MySQL 전체 외부 조인 구현

MySQL은 `FULL OUTER JOIN` 문법을 직접 지원하지 않는다.

다음처럼 왼쪽 외부 조인 결과와 오른쪽에만 존재하는 행을 합칠 수 있다.

```sql
SELECT
  p.id AS player_id,
  p.nickname,
  g.id AS guild_id,
  g.name
FROM players AS p
LEFT JOIN guilds AS g
  ON g.id = p.guild_id

UNION ALL

SELECT
  p.id AS player_id,
  p.nickname,
  g.id AS guild_id,
  g.name
FROM players AS p
RIGHT JOIN guilds AS g
  ON g.id = p.guild_id
WHERE p.id IS NULL;
```

두 번째 분기에서 이미 첫 번째 결과에 포함된 일치 행을 제외하기 때문에 `UNION ALL`을 사용할 수 있다.

### MongoDB에서 양쪽 데이터를 모두 유지해야 하는 경우

MongoDB의 `$lookup`은 기본적으로 현재 조회 중인 컬렉션을 기준으로 동작한다.

따라서 SQL의 `FULL OUTER JOIN`처럼 양쪽의 일치하지 않는 데이터까지 모두 유지하려면 일반적인 `$lookup` 하나만으로 처리하는 것보다 여러 aggregation 단계를 조합해야 한다.

구조가 복잡해질 수 있으므로 실제 요구사항에 따라 데이터 모델을 먼저 검토하는 것이 좋다.

## 다중 테이블 조인

```sql
SELECT
  p.nickname,
  g.name AS guild_name,
  i.name AS item_name,
  pi.quantity
FROM players AS p
LEFT JOIN guilds AS g
  ON g.id = p.guild_id
JOIN player_items AS pi
  ON pi.player_id = p.id
JOIN items AS i
  ON i.id = pi.item_id
ORDER BY p.nickname, i.name;
```

N:M 관계에서는 다음 순서로 연결 테이블을 거친다.

```text
players
   |
   v
player_items
   |
   v
items
```

즉

```text
players -> player_items -> items
```

순서로 연결한다.

### MongoDB의 다중 `$lookup`

MongoDB에서도 여러 번 `$lookup`을 사용할 수 있다.

```js
db.players.aggregate([
  {
    $lookup: {
      from: "guilds",
      localField: "guildId",
      foreignField: "_id",
      as: "guild",
    },
  },
  {
    $unwind: {
      path: "$guild",
      preserveNullAndEmptyArrays: true,
    },
  },
  {
    $lookup: {
      from: "player_items",
      localField: "_id",
      foreignField: "playerId",
      as: "playerItems",
    },
  },
  {
    $unwind: "$playerItems",
  },
  {
    $lookup: {
      from: "items",
      localField: "playerItems.itemId",
      foreignField: "_id",
      as: "item",
    },
  },
  {
    $unwind: "$item",
  },
  {
    $project: {
      _id: 0,
      nickname: 1,
      guildName: "$guild.name",
      itemName: "$item.name",
      quantity: "$playerItems.quantity",
    },
  },
  {
    $sort: {
      nickname: 1,
      itemName: 1,
    },
  },
]);
```

MongoDB에서도 N:M 관계를 참조 방식으로 설계했다면 연결 컬렉션을 거쳐 여러 번 `$lookup`할 수 있다.

다만 `$lookup`이 많아지면 조회 비용이 커질 수 있으므로 실제 조회 패턴을 고려하여 Embedding과 Referencing을 선택해야 한다.

## 자기 조인(Self Join)

같은 테이블 안에서 멘토와 멘티 관계를 표현할 수 있다.

```sql
ALTER TABLE players
ADD COLUMN mentor_id BIGINT UNSIGNED NULL,
ADD CONSTRAINT fk_players_mentor
  FOREIGN KEY (mentor_id) REFERENCES players(id)
  ON DELETE SET NULL;
```

```sql
SELECT
  mentee.nickname AS mentee_name,
  mentor.nickname AS mentor_name
FROM players AS mentee
LEFT JOIN players AS mentor
  ON mentor.id = mentee.mentor_id;
```

동일한 테이블을 두 역할로 사용하므로 의미가 드러나는 별칭이 중요하다.

```text
players AS mentee
players AS mentor
```

### MongoDB의 자기 참조

MongoDB에서도 같은 컬렉션을 `$lookup`할 수 있다.

플레이어 문서가 다음과 같다고 가정한다.

```js
{
  _id: ObjectId("player2"),
  nickname: "Alice",
  mentorId: ObjectId("player1")
}
```

같은 `players` 컬렉션을 대상으로 `$lookup`한다.

```js
db.players.aggregate([
  {
    $lookup: {
      from: "players",
      localField: "mentorId",
      foreignField: "_id",
      as: "mentor",
    },
  },
  {
    $unwind: {
      path: "$mentor",
      preserveNullAndEmptyArrays: true,
    },
  },
  {
    $project: {
      _id: 0,
      menteeName: "$nickname",
      mentorName: "$mentor.nickname",
    },
  },
]);
```

SQL의 Self Join과 같은 개념으로 볼 수 있다.

## `CROSS JOIN`

- 양쪽 테이블의 모든 조합인 카테시안 곱(Cartesian Product)을 만든다.

```sql
SELECT
  p.nickname,
  i.name AS item_name
FROM players AS p
CROSS JOIN items AS i;
```

플레이어가 10명이고 아이템이 100개라면

```text
10 × 100 = 1,000
```

총 1,000행이 만들어진다.

의도하지 않은 대량 결과가 생기지 않도록 주의해야 한다.

### MongoDB에서 모든 조합 만들기

MongoDB에서도 `$lookup`의 pipeline을 이용해 모든 문서를 연결할 수 있다.

```js
db.players.aggregate([
  {
    $lookup: {
      from: "items",
      pipeline: [],
      as: "items",
    },
  },
  {
    $unwind: "$items",
  },
  {
    $project: {
      _id: 0,
      nickname: 1,
      itemName: "$items.name",
    },
  },
]);
```

플레이어 10명과 아이템 100개가 있다면 결과는 마찬가지로 최대 1,000개의 조합이 만들어질 수 있다.

## 집합 연산자

`JOIN`은 열 방향으로 테이블을 결합하고, 집합 연산자는 행 방향으로 조회 결과를 결합한다.

| 연산자      | 결과                              |
| ----------- | --------------------------------- |
| `UNION`     | 합집합, 중복 제거                 |
| `UNION ALL` | 합집합, 중복 유지                 |
| `INTERSECT` | 교집합                            |
| `EXCEPT`    | 첫 결과에서 둘째 결과를 뺀 차집합 |

```sql
SELECT nickname
FROM players
WHERE level >= 40

UNION

SELECT nickname
FROM players
WHERE vip_grade >= 4;
```

집합 연산 조건은 다음과 같다.

- 각 `SELECT`의 열 개수가 같아야 한다
- 같은 위치의 열 자료형은 서로 호환되어야 한다
- 최종 열 이름은 일반적으로 첫 번째 `SELECT`를 따른다
- 전체 결과 정렬은 마지막에 한 번 작성한다

```sql
SELECT
  nickname,
  level
FROM players
WHERE guild_id = 1

UNION ALL

SELECT
  nickname,
  level
FROM players
WHERE guild_id = 2

ORDER BY level DESC, nickname ASC;
```

MySQL 버전에 따라 `INTERSECT`, `EXCEPT` 지원 여부가 다를 수 있으므로 사용 중인 버전을 확인해야 한다.

호환성이 중요하면 `JOIN`, `EXISTS`, `NOT EXISTS` 등으로 대체할 수 있다.

## MongoDB에서 집합 결합

MongoDB에서는 `$unionWith`를 사용하여 다른 컬렉션이나 파이프라인 결과를 이어 붙일 수 있다.

SQL의 `UNION ALL`과 비슷하게 생각할 수 있다.

```js
db.players.aggregate([
  {
    $match: {
      guildId: ObjectId("guild1"),
    },
  },
  {
    $project: {
      _id: 0,
      nickname: 1,
      level: 1,
    },
  },
  {
    $unionWith: {
      coll: "players",
      pipeline: [
        {
          $match: {
            guildId: ObjectId("guild2"),
          },
        },
        {
          $project: {
            _id: 0,
            nickname: 1,
            level: 1,
          },
        },
      ],
    },
  },
]);
```

`$unionWith`는 기본적으로 중복을 자동 제거하지 않는다.

따라서 SQL의 `UNION ALL`과 더 비슷하다.

중복을 제거하려면 이후 `$group` 등을 추가할 수 있다.

```js
db.players.aggregate([
  {
    $match: {
      level: {
        $gte: 40,
      },
    },
  },
  {
    $project: {
      _id: 0,
      nickname: 1,
    },
  },
  {
    $unionWith: {
      coll: "players",
      pipeline: [
        {
          $match: {
            vipGrade: {
              $gte: 4,
            },
          },
        },
        {
          $project: {
            _id: 0,
            nickname: 1,
          },
        },
      ],
    },
  },
  {
    $group: {
      _id: "$nickname",
    },
  },
  {
    $project: {
      _id: 0,
      nickname: "$_id",
    },
  },
]);
```

## `JOIN` 성능 점검

- 조인 열의 자료형과 부호가 일치하는지 확인

- 기본키, 외래키와 자주 사용하는 조인 열의 인덱스를 확인

- 필요한 열만 조회

- 불필요한 N:M 확장으로 행 수가 폭증하지 않는지 확인

- 실제 실행 계획은 `EXPLAIN`으로 확인

```sql
EXPLAIN
SELECT
  p.nickname,
  g.name
FROM players AS p
JOIN guilds AS g
  ON g.id = p.guild_id
WHERE p.level >= 30;
```

## MongoDB `$lookup` 성능 점검

MongoDB에서 `$lookup`을 사용할 때도 연결 기준 필드의 인덱스를 고려해야 한다.

예를 들어

```js
db.players.aggregate([
  {
    $lookup: {
      from: "guilds",
      localField: "guildId",
      foreignField: "_id",
      as: "guild",
    },
  },
]);
```

다음과 같은 부분을 확인한다.

- `localField`, `foreignField`의 데이터 타입이 일치하는지
- 연결 대상 필드에 적절한 인덱스가 있는지
- 불필요한 `$lookup`을 반복하지 않는지
- `$unwind`로 결과 문서 수가 크게 증가하지 않는지
- 필요한 필드만 `$project`하는지
- 가능한 경우 `$match`를 앞쪽에 배치해 처리할 문서 수를 줄이는지

MongoDB에서도 실제 실행 계획을 확인할 수 있다.

```js
db.players.explain("executionStats").aggregate([
  {
    $lookup: {
      from: "guilds",
      localField: "guildId",
      foreignField: "_id",
      as: "guild",
    },
  },
]);
```

## MongoDB의 `$lookup`

```js
db.players.aggregate([
  {
    $lookup: {
      from: "guilds",
      localField: "guildId",
      foreignField: "_id",
      as: "guild",
    },
  },
  {
    $unwind: {
      path: "$guild",
      preserveNullAndEmptyArrays: true,
    },
  },
  {
    $project: {
      _id: 0,
      nickname: 1,
      guildName: "$guild.name",
    },
  },
]);
```

`$lookup`은 관계형 데이터베이스의 왼쪽 외부 조인과 비슷한 결과를 만들 수 있다.

`$unwind`의 `preserveNullAndEmptyArrays` 설정에 따라 일치하지 않는 문서를 유지할 수 있다.

```text
preserveNullAndEmptyArrays: true
-> 연결되는 문서가 없어도 원본 문서 유지

preserveNullAndEmptyArrays: false
또는 일반적인 $unwind
-> 연결되는 문서가 없으면 결과에서 제외될 수 있음
```

## 핵심 정리

- `INNER JOIN`은 양쪽에서 조건이 일치하는 행만 조회

- `LEFT JOIN`은 왼쪽 모든 행을 유지

- `RIGHT JOIN`은 오른쪽 모든 행을 유지하지만 테이블 순서를 변경한 `LEFT JOIN`으로 표현할 수 있음

- 외부 조인에서 조건을 `ON`과 `WHERE` 중 어디에 두는지에 따라 결과가 달라진다

- N:M 관계는 연결 테이블을 거쳐 조인한다

- 자기 조인에서는 같은 테이블에 서로 다른 역할의 별칭을 준다

- `CROSS JOIN`은 두 테이블의 모든 조합을 만든다

- `JOIN`은 열 방향, 집합 연산자는 행 방향으로 결합한다

- `UNION`은 중복을 제거하고 `UNION ALL`은 중복을 유지한다

- MongoDB에서는 `$lookup`으로 다른 컬렉션을 연결할 수 있다

- MongoDB의 `$lookup` 결과는 기본적으로 배열이므로 필요에 따라 `$unwind`를 사용한다

- MongoDB에서는 `$unionWith`를 사용하여 여러 조회 결과를 행 방향과 비슷하게 결합할 수 있다

# 복습 문제

## 1. 길드가 없는 플레이어까지 조회하는 조인을 작성

`INNER JOIN`을 사용하면 길드가 없는 플레이어는 조회되지 않는다.

따라서 모든 플레이어를 유지해야 하므로 `LEFT JOIN`을 사용한다.

```sql
SELECT
  p.id,
  p.nickname,
  g.name AS guild_name
FROM players AS p
LEFT JOIN guilds AS g
  ON g.id = p.guild_id
ORDER BY p.id;
```

길드가 있는 플레이어는 `guild_name`에 길드명이 나오고, 길드가 없는 플레이어는 `NULL`이 나온다.

```text
id | nickname | guild_name
---|----------|------------
1  | Neo      | Red Knights
2  | Alice    | NULL
```

즉

```text
players를 모두 유지
+
일치하는 guilds가 있으면 연결
+
없으면 guilds 쪽 값은 NULL
```

MongoDB에서는 `$lookup`과 `$unwind`의 `preserveNullAndEmptyArrays: true`를 사용할 수 있다.

```js
db.players.aggregate([
  {
    $lookup: {
      from: "guilds",
      localField: "guildId",
      foreignField: "_id",
      as: "guild",
    },
  },
  {
    $unwind: {
      path: "$guild",
      preserveNullAndEmptyArrays: true,
    },
  },
  {
    $project: {
      _id: 0,
      nickname: 1,
      guildName: "$guild.name",
    },
  },
]);
```

## 2. 플레이어가 한 명도 없는 길드를 찾는 쿼리를 작성

모든 길드를 유지한 다음 플레이어가 연결되지 않은 길드만 찾는다.

```sql
SELECT
  g.id,
  g.name
FROM guilds AS g
LEFT JOIN players AS p
  ON p.guild_id = g.id
WHERE p.id IS NULL;
```

처리 과정은 다음과 같다.

```text
guilds 전체 유지
        ↓
players 연결
        ↓
연결되는 player가 없는 경우
p.id = NULL
        ↓
WHERE p.id IS NULL
```

MongoDB에서는 `guilds`를 기준으로 `players`를 `$lookup`한 뒤 빈 배열을 찾을 수 있다.

```js
db.guilds.aggregate([
  {
    $lookup: {
      from: "players",
      localField: "_id",
      foreignField: "guildId",
      as: "players",
    },
  },
  {
    $match: {
      players: {
        $eq: [],
      },
    },
  },
  {
    $project: {
      _id: 1,
      name: 1,
    },
  },
]);
```

## 3. 외부 조인에서 오른쪽 테이블 조건을 `WHERE`에 두면 어떤 문제가 생길 수 있는가?

`LEFT JOIN`은 원래 왼쪽 테이블의 모든 행을 유지한다.

하지만 오른쪽 테이블의 조건을 `WHERE`에 작성하면 오른쪽 데이터가 없는 경우 발생하는 `NULL` 행이 제거될 수 있다.

예를 들어 다음 쿼리가 있다.

```sql
SELECT
  g.name,
  p.nickname,
  p.level
FROM guilds AS g
LEFT JOIN players AS p
  ON p.guild_id = g.id
WHERE p.level >= 30;
```

플레이어가 없는 길드는 다음과 같이 만들어진다.

```text
guild      | player | level
-----------|--------|------
Red        | Neo    | 40
Blue       | NULL   | NULL
```

하지만

```sql
WHERE p.level >= 30
```

조건에서

```text
NULL >= 30
```

은 참이 아니므로 해당 행은 결과에서 제거된다.

따라서 `LEFT JOIN`을 사용했지만 결과가 `INNER JOIN`과 비슷하게 변할 수 있다.

모든 길드를 유지하면서 레벨 30 이상 플레이어만 연결하려면 조건을 `ON`에 작성한다.

```sql
SELECT
  g.name,
  p.nickname,
  p.level
FROM guilds AS g
LEFT JOIN players AS p
  ON p.guild_id = g.id
 AND p.level >= 30;
```

핵심은 다음과 같다.

```text
ON 조건
-> 연결할 오른쪽 행을 결정
-> 왼쪽 행 자체는 유지

WHERE 조건
-> JOIN이 끝난 최종 결과에서 행을 제거
```

## 4. `UNION`과 `UNION ALL`의 차이

`UNION`은 여러 조회 결과를 합치면서 중복 행을 제거한다.

```sql
SELECT nickname
FROM players
WHERE level >= 40

UNION

SELECT nickname
FROM players
WHERE vip_grade >= 4;
```

예를 들어 각각의 결과가 다음과 같다고 가정한다.

```text
첫 번째 SELECT

Neo
Alice
```

```text
두 번째 SELECT

Neo
Bob
```

`UNION` 결과는 다음과 같다.

```text
Neo
Alice
Bob
```

`Neo`는 중복 제거된다.

반면 `UNION ALL`은 중복을 유지한다.

```sql
SELECT nickname
FROM players
WHERE level >= 40

UNION ALL

SELECT nickname
FROM players
WHERE vip_grade >= 4;
```

결과:

```text
Neo
Alice
Neo
Bob
```

정리하면

| 연산자      | 중복 처리 | 특징                |
| ----------- | --------- | ------------------- |
| `UNION`     | 제거      | 중복 제거 작업 필요 |
| `UNION ALL` | 유지      | 결과를 그대로 결합  |

중복 제거가 필요하지 않다면 일반적으로 `UNION ALL`이 불필요한 중복 제거 작업을 하지 않는다.

MongoDB에서는 `$unionWith`가 기본적으로 중복을 유지하므로 `UNION ALL`과 비슷하다.

## 5. 플레이어, 보유 아이템, 수량을 조회하는 3테이블 조인 작성

다음 세 테이블을 사용한다고 가정한다.

```text
players
player_items
items
```

관계는 다음과 같다.

```text
players
   |
   | 1:N
   v
player_items
   |
   | N:1
   v
items
```

SQL:

```sql
SELECT
  p.nickname,
  i.name AS item_name,
  pi.quantity
FROM players AS p
JOIN player_items AS pi
  ON pi.player_id = p.id
JOIN items AS i
  ON i.id = pi.item_id
ORDER BY p.nickname, i.name;
```

예를 들어

```text
players

id | nickname
---|---------
1  | Neo
```

```text
items

id | name
---|-------
10 | Sword
20 | Potion
```

```text
player_items

player_id | item_id | quantity
----------|---------|---------
1         | 10      | 1
1         | 20      | 5
```

조회 결과:

```text
nickname | item_name | quantity
---------|-----------|---------
Neo      | Potion    | 5
Neo      | Sword     | 1
```

MongoDB에서 참조형 구조를 사용했다면 여러 번 `$lookup`할 수 있다.

```js
db.players.aggregate([
  {
    $lookup: {
      from: "player_items",
      localField: "_id",
      foreignField: "playerId",
      as: "playerItems",
    },
  },
  {
    $unwind: "$playerItems",
  },
  {
    $lookup: {
      from: "items",
      localField: "playerItems.itemId",
      foreignField: "_id",
      as: "item",
    },
  },
  {
    $unwind: "$item",
  },
  {
    $project: {
      _id: 0,
      nickname: 1,
      itemName: "$item.name",
      quantity: "$playerItems.quantity",
    },
  },
]);
```

## 6. `CROSS JOIN`의 결과 행 수를 계산하는 방법 설명

`CROSS JOIN`은 왼쪽 테이블의 모든 행과 오른쪽 테이블의 모든 행을 조합한다.

따라서 결과 행 수는 다음과 같다.

```text
왼쪽 테이블 행 수 × 오른쪽 테이블 행 수
```

예를 들어

```text
players = 10행
items = 100행
```

이라면

```text
10 × 100 = 1,000행
```

의 결과가 만들어진다.

```sql
SELECT
  p.nickname,
  i.name AS item_name
FROM players AS p
CROSS JOIN items AS i;
```

예를 들어 플레이어가

```text
Neo
Alice
```

이고 아이템이

```text
Sword
Shield
Potion
```

이라면 결과는

```text
Neo   + Sword
Neo   + Shield
Neo   + Potion

Alice + Sword
Alice + Shield
Alice + Potion
```

총

```text
2 × 3 = 6행
```

이다.

따라서 `CROSS JOIN`은 데이터가 많을수록 결과가 매우 빠르게 증가할 수 있으므로 주의해야 한다.

MongoDB에서도 모든 아이템을 각 플레이어에게 `$lookup`한 뒤 `$unwind`하면 비슷한 결과를 만들 수 있다.

```js
db.players.aggregate([
  {
    $lookup: {
      from: "items",
      pipeline: [],
      as: "items",
    },
  },
  {
    $unwind: "$items",
  },
  {
    $project: {
      _id: 0,
      nickname: 1,
      itemName: "$items.name",
    },
  },
]);
```

핵심 공식:

```text
CROSS JOIN 결과 행 수
=
왼쪽 행 수 × 오른쪽 행 수
```
